# AGENTS.md

This file provides guidance to AI coding agents (Claude Code, etc.) when working with code in this repository. CLAUDE.md is a symlink to this file.

`ultralytics/yolo-ios-app` (AGPL-3.0) ships three things: the `UltralyticsYOLO` Swift package (`Sources/UltralyticsYOLO/`, also the `UltralyticsYOLO` CocoaPod) that runs Core ML exports of Ultralytics YOLO models through Vision for detect, segment, semantic, depth, classify, pose, and OBB; the App Store app in `YOLOiOSApp/` (bundle id `com.ultralytics.iDetection`) built on that package; and four sample projects in `ExampleApps/`. Zero third-party dependencies anywhere — Apple first-party frameworks only (Foundation, Core ML, Vision, AVFoundation, Accelerate, Compression, UIKit/SwiftUI); even ZIP extraction is in-repo (`MiniZip.swift`). The version lives in two places that must match: `MARKETING_VERSION` in `YOLOiOSApp/YOLOiOSApp.xcodeproj/project.pbxproj` and `s.version` in `UltralyticsYOLO.podspec` (currently `8.9.14`).

## Core Principles (CRITICAL)

**Less is more. The simplest solution is the best solution.** The action hierarchy for every change: **Delete > Replace > Add**.

1. **Solve at the owner**: Put behavior in the code path that owns or observes it. For fixes, never guard a symptom with a staleness check, initialization flag, skip-first-call branch, or `try/except` around broken logic; relocate the trigger and delete the wrong path. For features, extend the existing owner rather than creating a parallel abstraction.
2. **Search and reuse first**: Search the whole repository before creating a feature, component, helper, workflow, or utility. Reuse or adapt what exists, consolidate in-scope duplication in the shared owner, and delete duplicate paths. Three similar lines beat a helper nobody else calls.
3. **Delete and modify existing code before creating new code**: Bugfixes are net-negative by default unless deletion and relocation are demonstrably impossible. A new file must first prove it cannot fit cleanly in an existing owner.
4. **Keep scope minimal**: Implement only the simplest complete solution. Avoid impossible-state handling, speculative flags, compatibility shims, policy scaffolding, and unrelated cleanup. Tests are out of scope by default — rely on existing coverage and focused validation; only an uncovered, high-risk regression path justifies minimal new test code.
5. **Ship zero-regression, production-ready changes**: Understand what you remove instead of retaining broken code as insurance. Remove unused imports, functions, types, files, and comments; run relevant cleanup checks; and thoroughly debug and validate the changed owner. Do not break existing features or workflows unless the PR intentionally removes them with evidence.

**Review gate:** for every addition, the reviewer decides whether deleting or changing existing code would have fixed the problem instead — if it would, that is a blocking finding. A missing or thin PR description is never itself a finding.

NEVER push to `main`. NEVER force push. Always start work in a new git worktree (`git worktree add`) on a feature branch and open a PR — never edit the primary checkout directly, it may hold in-flight work.

## PR Workflow

After opening a PR:

1. Wait for the automated PR review and auto-format commit from Ultralytics Actions (`format.yml`), then pull and address every finding.
2. Review the full diff in-session against the Core Principles, performance, and the review gate above, then batch the fixes into one commit and push. After each round of bot or human commits, pull and resume the same reviewer on `<last-reviewed-sha>..HEAD` plus anything that delta could have invalidated. Repeat until the local head matches the live head.
3. Hand off or merge only on a clean final pass: one cold full-diff review returning LGTM with no findings, on a head that is still live at merge time.
4. Never fight other commits: Ultralytics Actions pushes auto-format and header commits, and multiple users may work on the same PR. `git pull --rebase` before pushing; never reset or revert commits you did not author.
5. After the PR merges, clean up: remove local worktrees and branches for it, then `git checkout main && git pull`.

## Conventions

- License header `// Ultralytics 🚀 AGPL-3.0 License - https://ultralytics.com/license` on every source file (`#` form for shell/Python/YAML) — Ultralytics Actions adds it automatically; don't add or revert it manually.
- Formatting is enforced by `format.yml` pushing commits onto PRs (swift-format, Prettier, shfmt, codespell, Ruff for Python) — pull its commits instead of re-formatting locally.
- Tests are XCTest in `Tests/YOLOTests`; model-backed tests load `.mlpackage` bundles from test resources (run the download script first) and none hit the live network.
- Releases: bump `MARKETING_VERSION` (two build configurations in `project.pbxproj`) and `s.version` in `UltralyticsYOLO.podspec` together in the release PR; merging to `main` then auto-tags, releases, and publishes the pod. The SPM `from:` version in `README.md`, `README.zh-CN.md`, and `Sources/UltralyticsYOLO/README.md` is refreshed to the latest released tag alongside. `ultralytics/yolo-flutter-app` consumes the pod as `'>= 8.9.14', '< 9.0'`, so a public API break there is a `9.0` change.
- Archive app builds auto-bump `CFBundleVersion` in `YOLOiOSApp/YOLOiOSApp/Info.plist` (a Run Script phase gated on `ACTION == install`) — never commit a stray build-number bump.
- `README.md` and `README.zh-CN.md` are translations of each other — apply any README change to both. `Sources/UltralyticsYOLO/README.md` is the package README (API usage, asset tables) and `docs/performance.md` is the canonical profiling record; update them when public API or shipped configuration changes.
- Task order in user-facing tables, `appTasks`, `remoteModelsInfo`, the export matrix, and the download script is `detect, segment, semantic, depth, classify, pose, obb`.
- Model naming: `yolo26{n,s,m,l,x}{"",-seg,-sem,-depth,-cls,-pose,-obb}`; official assets are int8 `.mlpackage.zip` archives at `https://github.com/ultralytics/yolo-ios-app/releases/download/v8.3.0/<model>.mlpackage.zip`, 224×224 input for classify and 640×640 for every other task, exported with `nms=False`.

## Architecture

Paths below are relative to `Sources/UltralyticsYOLO/` unless they start with `YOLOiOSApp/`, `Tests/`, `ExampleApps/`, `scripts/`, or `docs/`.

**Request flow.** `YOLO` (`YOLO.swift`) is the still-image facade: `init(_ modelPathOrName:task:...)` resolves the model through `ModelPathResolver.resolve` (a filesystem path ending in `.mlmodel`/`.mlpackage`/`.mlmodelc`, otherwise a `Bundle.main` resource looked up as `.mlmodelc` then `.mlpackage`), `init(url:task:...)` first runs `YOLOModelDownloader.download` (cached in `YOLOModelCache`), and both then call `BasePredictor.create(for:modelURL:useGpu:numItemsThreshold:)` — the single task → class switch (`ObjectDetector`, `Segmenter`, `SemanticSegmenter`, `DepthEstimator`, `Classifier`, `PoseEstimator`, `ObbDetector`). The generic `create(unwrappedModelURL:...)` in `BasePredictor.swift` does the load on a `.userInitiated` global queue: compiles non-`.mlmodelc` URLs with `MLModel.compileModel` on every load, picks `MLModelConfiguration.computeUnits` (`useGpu: true` → `.cpuAndNeuralEngine` on iOS 16+, `.all` below; `false` → `.cpuOnly`), parses class labels from the `classes`/`names` creator-defined metadata (`parseLabels(from:)`, public), sets `requiresNMS` (false when metadata `nms` is `"false"` or, absent metadata, when some output has shape `[1, N≤1000, 6]`), reads `modelInputSize` from the image input constraint, and wraps the model in a `VNCoreMLModel` whose `featureProvider` is a `ThresholdProvider` (`iouThreshold` forced to `1.0` for NMS-free models, so the IoU slider is a no-op for YOLO26) plus a `VNCoreMLRequest` using the predictor's `imageCropAndScaleOption` (`.scaleFit` letterbox; `Classifier` overrides to `.centerCrop`). Completion fires on the main thread; `YOLO.isLoaded` is false until then and every `callAsFunction` overload returns `YOLOResult.empty` before that. Inference is synchronous: `predictOnImage(image:)` (stills) and `predict(sampleBuffer:...)` (camera, via `VideoCapture`) both call `VNImageRequestHandler.perform` on the caller's thread and decode immediately — the "inference time" therefore includes Vision's fused preprocessing (`preMs` is always 0 on iOS).

- `Predictor.swift` — the `Predictor` protocol (`predict(sampleBuffer:onResultsListener:onInferenceTime:)`, `predictOnImage(image:)`, `labels`, `isUpdating`), the `ResultsListener`/`InferenceTimeListener` callbacks, and `PredictorError.modelFileNotFound`. `YOLOTask.swift` — the seven cases plus `YOLOTask.fromString`, which accepts bridge aliases (`"segmentation"`, `"cls"`, `"oriented-bounding-box"`, ...) and defaults to `.detect` for anything unknown.
- `BasePredictor.swift` — everything shared. Subclass hooks: `processObservations(for:_:)` (camera path; must call `markInferenceEnd()`, `updateTime()`, `applyTimingBreakdown(&result, smoothed: true)`, then `currentOnResultsListener?.on(result:)`), `predictOnImage(image:)` (still path; `finishTiming(notify: false)` before drawing so annotation is excluded from `speed`), and `imageCropAndScaleOption`. Helpers: `makeRequestHandler(for:)` (records `inputSize` and `t0`), `perform(_:with:errorMessage:)`, `firstFeatureArray(_:)`, `labelName(for:)` (falls back to `"class <i>"`). Coordinate mapping all derives from the private `letterboxTransform` (`gain = min(modelH/inputH, modelW/inputW)`, centered `padX`/`padY` with the same `-0.1` rounding as Ultralytics `LetterBox`): `inputRect(fromModelRect:)`, `normalizedRect(fromInputRect:)`, `inputPoint(fromModelPoint:)`, `normalizedPoint(fromInputPoint:)`, `inputOBB(fromModelOBB:)`, and `inputMaskCropRect(maskWidth:maskHeight:inputSize:modelInputSize:)` (nil when nothing to crop). Thresholds: `confidenceThreshold` 0.25, `iouThreshold` 0.7, `numItemsThreshold` 30 — the setters rebuild the `ThresholdProvider`; `numItemsThreshold` is applied Swift-side with `prefix`. Timing: `t0`/`t1`/`tInferEnd` raw, `t2`/`t2Infer`/`t2Post`/`t4` EMA-smoothed (`emaAlpha` 0.05) for the camera path; `YOLOResult.speed` is seconds while listeners receive milliseconds. `capturesOriginalImage` and `capturesInstanceMasks` are opt-in per-frame costs used by the Flutter plugin.
- Task decoders — every decoder branches on the raw `MLMultiArray` shape and always indexes through `strides`; non-`float32` tensors must be read through the subscript (see `ObjectDetector.processRawResults`, #303):
  - `ObjectDetector.swift`: `VNRecognizedObjectObservation` results (Core ML/Vision NMS pipeline, YOLO11 `nms=True`) or a raw tensor — `[1, max_det, 6]` end2end `xyxy` pixels + conf + class (`shape[2] < shape[1]`) vs `[1, 4+nc, anchors]` traditional `xywh` followed by `nonMaxSuppression(boxes:scores:threshold:)` from `NonMaxSuppression.swift`.
  - `Segmenter.swift`: two outputs — the 4-D one is the prototype tensor `[1, 32, H, W]`, the other is `[1, max_det, 6+32]` or `[1, 4+nc+32, anchors]` (per-class NMS). Mask compositing is `generateCombinedMaskImage` in `Plot.swift` (`vDSP_mmul` coefficients × protos, letterbox crop via `inputMaskCropRect`, upscale to input resolution); the camera path runs it on a background queue and only materializes per-instance masks when `capturesInstanceMasks` is set.
  - `SemanticSegmenter.swift`: `[1, H, W]` class map (in-graph ArgMax, `int32` or float — current exports) or logits `[1, C, H, W]`/`[1, H, W, C]` (layout inferred from the shape and `labels.count`); one channel → threshold; colors via vImage lookup tables (scalar fallback above 256 classes).
  - `DepthEstimator.swift`: `[1, 1, H, W]` or `[H, W]` metric meters; values ≤ 0 are invalid (transparent); `minDepth`/`maxDepth` over valid pixels; log-normalized color ramp.
  - `Classifier.swift`: `VNClassificationObservation` or raw logits → `softmaxProbs` (vDSP softmax, linear top-5 selection); `Probs.top1Label`/`top5Labels` are Flutter compatibility aliases.
  - `PoseEstimator.swift`: `[1, max_det, 6+51]` (or `5+51` without the class field) vs `[1, 56, anchors]` + NMS; keypoints returned as `Keypoints(xyn:xy:conf:)`. Skeleton and palettes (`skeleton`, `posePalette`, `limbColorIndices`, `kptColorIndices`) live in `Plot.swift`.
  - `ObbDetector.swift`: `[1, max_det, 7]` = `cx, cy, w, h, conf, class, angle` (center-based, radians — NOT `xyxy`) vs `[1, 4+nc+1, anchors]` + `nonMaxSuppressionOBB` (AABB prefilter, then Sutherland–Hodgman polygon IoU via `OBBInfo`). `OBB` values are normalized to the input image after padding removal; `OBB.toPolygon()` (normalized), `toPolygon(imageSize:)` (pixels), `toPolygon(in:)` (Flutter compatibility).
- `YOLOResult.swift` — `YOLOResult` (`orig_shape`, `boxes`, `masks`, `semanticMask`, `depthMap`, `probs`, `keypointsList`, `obb`, `annotatedImage`, `speed`, `fps`, `preMs`/`inferenceMs`/`postMs`, `originalImage`, `names`, `.empty`) and `Box` (`xywh` is a `CGRect` in input pixels, `xywhn` normalized), `Masks`, `SemanticMask` (`classMap` row-major `Int32`), `DepthMap`, `Probs`, `Keypoints`, `OBBResult`, `OBB`, `Polygon`.
- `Plot.swift` — `ultralyticsColors` (20-color palette, index = class % 20) and the still-image renderers used by `predictOnImage`: `drawYOLODetections`, `drawYOLOClassifications`, `drawYOLOPoseWithBoxes`, `drawYOLOSegmentationWithBoxes`, `drawYOLOSemanticSegmentation` (also used for depth), `drawOBBsOnCIImage`; `drawKeypoints` draws pose skeletons onto a `CALayer` for both paths. Label geometry shared with the live overlay lives in `DetectionLabelStyle` (`BoundingBoxView.swift`).
- Camera pipeline — `YOLOView.swift` (`@MainActor` `UIView`, `VideoCaptureDelegate`) owns a `VideoCapture`, the overlay/mask/pose `CALayer`s, a pool of 100 `BoundingBoxView`s (≤ 50 shown), and the built-in UI (conf/IoU/max-items sliders, FPS + pre/inference/post labels, play/pause, camera switch, lens control, torch, share, zoom, info sheet `YOLOInfoViewController`). `setModel(modelPathOrName:task:completion:)` resolves via `ModelPathResolver`, calls `BasePredictor.create(for:..., isRealTime: true)`, and swaps `videoCapture.predictor`. Results arrive in `onPredict(result:)`, which forwards to `delegate` (`YOLOViewDelegate`) and `onDetection` before drawing; set `showOverlays = false` to draw your own. Screen mapping is `aspectFillDisplayRect` (matches the preview layer's `.resizeAspectFill`). `captureSessionPreset` defaults to `.hd1280x720`; `capturePhoto(completion:)` returns the frozen frame with overlays burned in. `YOLOCamera.swift` is the SwiftUI wrapper (`YOLOViewRepresentable`; `.front` is applied via `pendingCameraPosition`). `VideoCapture.swift`: `AVCaptureSession` with `[requested, .high, .photo]` preset fallback, 32BGRA `AVCaptureVideoDataOutput` on `cameraQueue`, connection `videoOrientation` kept equal to the interface orientation so buffers arrive upright (`cameraFrameOrientation` is `.up`), iOS 16+ model-sized output buffers (`configureInferenceBufferSize`: long side = model input, aspect preserved, short side for center-crop models), one frame in flight (`predictor.isUpdating`), a dedicated `AVCapturePhotoOutput` whose still is run through `predictOnImage` so share overlays align, and delegate callbacks hopped to the main thread. Zoom/lens helpers (`bestCaptureDevice`, `zoomFactor(for:on:)`, `displayZoomFactor`) are top-level functions in the same file.
- Model download and cache (SDK) — `YOLOModelDownloader.swift` (`URLSession` download → `MiniZip.extract` skipping `__MACOSX`/`._*` → `findModelFile` for `.mlpackage`/`.mlmodel`/`.mlmodelc` → `MLModel.compileModel` → move into cache; one download at a time per instance; `DownloadError` cases) and `YOLOModelCache.swift` (`Library/Caches/YOLOModels/<sha256>.mlmodelc`, key = URL + `_mobile-standard-v1` for v8.3.0 release URLs + `_<task>`; `clearCache`, `getCacheSize`, `listCachedModels`). `MiniZip.swift` is the dependency-free ZIP reader (stored/deflate, zip64 and unsafe paths rejected, 1032× inflate cap). `UIImage+Orientation.swift` maps `UIImage.Orientation` → `CGImagePropertyOrientation` and `uprightForYOLO()`; `YOLO.callAsFunction(_ uiImage:)` re-applies orientation because `CIImage(image:)` drops it. `Logger.swift` `YOLOLog` writes to os_log subsystem `com.ultralytics.yolo`, category `YOLO` (and stdout in Debug).
- App (`YOLOiOSApp/YOLOiOSApp/`) — storyboard-driven `ViewController.swift` with a `YOLOView` IBOutlet. `appTasks` maps each task to a `Models/<Task>` folder reference in the Xcode project (blue folder → `Bundle.main.url(forResource: "Models/Detect", withExtension: nil)`); `getModelFiles(in:)` lists bundled `.mlpackage`/`.mlmodelc` there, so a custom model dropped into `YOLOiOSApp/Models/<Task>/` and added to the target shows up in the picker. `RemoteModels.swift` `remoteModelsInfo` builds the n–x × 7-task download registry from the v8.3.0 release; entries not bundled locally appear with a `⤓` prefix (`ModelSelectionManager.swift`, size segmented control, `taskSuffixes`). `ModelDownloadManager.swift` holds the app's own `ModelCacheManager` (Documents/`<key>-mobile-standard-v1.mlmodelc`, in-memory LRU of 3 `MLModel`s) and `ModelDownloadManager` — a separate cache from the SDK's `YOLOModelCache`. `ExternalDisplay/` is optional AirPlay/wired-monitor support gated by the `dedicated_external_display` toggle in `Settings.bundle/Root.plist` (`ExternalDisplayManager`, `ExternalSceneDelegate`, `ExternalViewController` hosting its own `YOLOView`, notifications in `NotificationExtensions.swift`); `AppDelegate.swift` registers its defaults, routes external scenes, and disables the idle timer. `Info.plist` has `UIFileSharingEnabled` (Documents visible in Files) and `UIRequiresFullScreen`.
- `ExampleApps/` — `YOLOSingleImageSwiftUI`, `YOLOSingleImageUIKit`, `YOLORealTimeSwiftUI`, `YOLORealTimeUIKit`, each an `.xcodeproj` depending on the package via the local path `../..`, with a model to be added to the **main app** target (tests read `Bundle.main`) and a `static let SKIP_MODEL_TESTS` in each test class. Not built in CI.
- `scripts/download-models.sh` — `MODELS` array (name → `Models/<Task>`), `BASE_URL` = v8.3.0, downloads with retries + `unzip -t` into `Tests/YOLOTests/Resources/` and copies into `YOLOiOSApp/Models/<Task>/`, skipping anything already present; verifies `Manifest.json`. Also run by the Xcode "Download YOLO Models" build phase (skipped when `GITHUB_ACTIONS=true`). `scripts/export-models.py` — `TASKS` spec (suffix, app folder, imgsz), `SIZES`, exports with `format="coreml", quantize=8, nms=False, imgsz=<224|640>` into `exports/coreml/` (expects or auto-downloads `<model>.pt` there), `verify_mlpackage` enforces one image input at the expected size and metadata `task`, `quantize=8`, `nms=False`, `end2end` (`True` for detect/segment/pose/obb), zips each `.mlpackage`, `--copy-to-app`, `--upload --repo --tag`.
- `docs/performance.md` — device-measured conclusions behind the shipped configuration: `.cpuAndNeuralEngine` (not `.all`), 720p preview + model-sized inference buffers, end2end `nms=False` exports (faster on-device than legacy + NMS), int8 (size only, no latency change), default `minimum_deployment_target`, FPS is camera-bound. Read it before touching compute units, presets, export args, or the timing code, and add a section when you change any of them.

## Where to look

- Boxes/masks/keypoints offset or scaled wrong → `BasePredictor.swift` (`letterboxTransform`, `inputRect`, `inputMaskCropRect`), then `VideoCapture.swift` orientation/mirroring (`updateVideoOrientation`, `configureVideoMirroring`, `configureInferenceBufferSize`), then `YOLOView.swift` `aspectFillDisplayRect`/`imageFrameInOverlay`. Regression tests: `Tests/YOLOTests/LetterboxTests.swift`, `BasePredictorTests` letterbox cases.
- Wrong or empty detections for a specific export → the task decoder's shape branch (`shape[2] < shape[1]` end2end test, field order, `strides`), `requiresNMS`/`hasNMSFreeDetectionOutput` in `BasePredictor.create`, and `ThresholdProvider`. Synthesize tensors with `makeArray` in `Tests/YOLOTests/BasePredictorTests.swift` instead of adding model files.
- Labels wrong or `"class 3"` → `BasePredictor.parseLabels(from:)` / `labelName(for:)`; the export's `names` metadata is the source.
- Model fails to load → `ModelPathResolver.swift` (extension check, bundle lookup order), `BasePredictor.create(unwrappedModelURL:)` (compile + `MLModelConfiguration`), and for URLs `YOLOModelDownloader.DownloadError` + `YOLOModelCache.cacheKey`. In the app: `ViewController.loadModel(entry:forTask:)` → `ModelCacheManager.loadModel`/`ModelDownloadManager.startDownload` → `loadCachedModelAndSetToYOLOView`.
- Timing/FPS numbers → `BasePredictor.updateTime`/`timingBreakdownMs`/`applyTimingBreakdown`, `YOLOView.onInferenceTime`/`onPredict` labels; smoothing constants `emaAlpha`/`maxValidDt`.
- Rendering/annotation → `Plot.swift` (stills), `YOLOView.showBoxes`/`showOBBs`/`overlayYOLOClassificationsCALayer`/mask layer in `onPredict` (live), `BoundingBoxView.swift` label style.
- Camera behavior (preset, lens, zoom, torch, photo capture, front mirroring) → `VideoCapture.swift` + `YOLOView.swift` (`start(position:)`, `switchCameraTapped`, `pinch`, `setTorchMode`, `capturePhoto`). Needs a device to verify.
- Adding a task: `YOLOTask` case + `fromString` aliases; predictor subclass + `BasePredictor.create(for:)` switch; result field in `YOLOResult.swift`; renderer in `Plot.swift`; `YOLOView.onPredict` + `setupSublayers`; app `appTasks` and a `YOLOiOSApp/Models/<Task>/.gitkeep` directory (the single `Models` folder reference in `project.pbxproj` bundles every subfolder), `RemoteModels.swift` tasks, `ModelSelectionManager.taskSuffixes`; `scripts/export-models.py` `TASKS`, `scripts/download-models.sh` `MODELS`, `Package.swift` test resources, `ci.yml`/README/test README model lists; and the `YOLOTask` exhaustive-switch compatibility note in `Sources/UltralyticsYOLO/README.md`.

## Gotchas

- `swift test` fails (UIKit/AVFoundation imports); always go through `xcodebuild` with an iOS Simulator destination. `Build/`, `.build/`, `.swiftpm/xcode/xcuserdata/`, `Package.resolved`, `*.pt`, and `*.mlpackage` are gitignored — never commit models or derived data (keep committed files under 1 MB).
- Model-backed tests (`Tests/YOLOTests/YOLOSSOTMergeTests.swift`) locate models with `#filePath` → `Tests/YOLOTests/Resources/<name>.mlpackage` and assert on existence rather than skipping, and each load compiles the package (30 s timeouts). Run `scripts/download-models.sh` first; everything else in `Tests/` is model-free.
- The periphery job is `--strict` with `--exclude-tests` and `--retain-public`: any non-`public` declaration in `Sources/` that is referenced only from `Tests/` (or not at all) fails CI. Make it `public`, use it in `Sources/`, or delete it.
- The coverage filter in `ci.yml` drops `BoundingBoxView`, `VideoCapture`, `YOLOCamera`, `YOLOInfoViewController`, `YOLOModelDownloader`, and `YOLOView` — CI never executes camera or download code; verify those on a device.
- `useGpu` is a misnomer kept for Flutter parity: `true` means ANE + CPU (`.cpuAndNeuralEngine`), the GPU is deliberately excluded in a live camera app. Do not switch to `.all` (measured slower/jitterier, `docs/performance.md`).
- YOLO26 (NMS-free) models ignore `iouThreshold` — the provider forces `1.0` and the decoders skip NMS — so IoU-slider bugs only reproduce with YOLO11 or `nms=None` exports. `confidenceThreshold` is applied both in the `ThresholdProvider` (Vision NMS pipeline) and Swift-side (`conf > confThreshold`).
- Every non-`.mlmodelc` load compiles with `MLModel.compileModel`; only `YOLOModelDownloader` persists the compiled `.mlmodelc`. Bundled `.mlpackage`s in the app recompile on each load.
- Two independent on-device model caches: SDK `YOLOModelCache` (`Library/Caches/YOLOModels`, SHA-256 keys) and app `ModelCacheManager` (`Documents/<key>-mobile-standard-v1.mlmodelc`). Replacing release assets in place without bumping the revision strings leaves devices on stale models.
- `YOLO.callAsFunction(_ remoteURL: URL?)` is deprecated because it blocks on `Data(contentsOf:)`; `YOLO(...)` init is asynchronous and inference before the completion returns `.empty`. Threshold setters called before load are stored as pending values and applied on load.
- `YOLOTask.fromString` silently returns `.detect` for unknown strings; a mis-typed task loads the wrong decoder rather than failing.
- `YOLOView.setModel` with an empty `modelPathOrName` completes with `PredictorError.modelFileNotFound` — `YOLOView(frame:)` without a model only starts the camera preview.
- Prettier formats `docs/*.md` with `--tab-width 4` but every other Markdown file with the default width; swift-format runs with defaults (no `.swift-format` file) — do not add a config file to change style.
- Semantic exports without `names` metadata make the NCHW/NHWC axis inference guess from shape alone (`YOLOLog.warning`); depth treats non-positive values as holes; classification center-crops, so `xywh`-style geometry does not apply.
- `ExampleApps/*` projects reference the package by relative path; opening several at once confuses Xcode's package resolution — open one at a time.

## Tests

- `Tests/YOLOTests/` (XCTest, `@testable import UltralyticsYOLO`): `BasePredictorTests.swift` (thresholds, timing, letterbox mapping, every decoder's traditional and end2end tensor layouts built with the file-private `makeArray(shape:writeValues:)` helper and `MockVNRequest`), `LetterboxTests.swift` (16:9 and 4:3 in both orientations round-trip through `inputRect`), `SemanticSegmenterTests.swift`, `DepthEstimatorTests.swift`, `ClassifierTests.swift` (top-k vs full sort), `PlotTests.swift` (renderers, palettes, `generateCombinedMaskImage`, label placement), `MiniZipTests.swift` (base64 fixture, garbage/truncated/bomb inputs), `ThresholdProviderTests.swift`, `UIImageOrientationTests.swift`, `YOLOResultTests.swift`, `YOLOTaskTests.swift`, `YOLOMainTests.swift` (`YOLO` facade with a `MockPredictor`, `YOLOModelCache` behavior), `YOLOIntegrationTests.swift` (result plumbing, boundary values, thread safety), and `YOLOSSOTMergeTests.swift` — the only suite that loads the seven real `.mlpackage`s (NMS-free IoU pinning, label fallbacks, `numItemsThreshold` at create/load, representative `predictOnImage` output shapes per task).

- CI runs the whole `YOLOTests` target on the first available iPhone simulator on `macos-26` with coverage; there are no device, UI, camera, example-app, or Python tests in CI.
